# dsh-plans

[English](README.md) | Русский

Все планы, которые сессия DeepSeek Harness представляла на проверку, — свежие сверху, в правой боковой панели и на странице рядом с Chat.

Режим плана и без плагина показывает план по одному: пока план ждёт решения, открывается его вкладка, а после хода в ленте остаётся карточка. Чего нет — общей истории сессии. Плагин её добавляет: все представленные планы с итогом, на токенах темы DSH, поэтому светлая и тёмная темы работают сразу.

## Что получаете

- **Список.** В правой панели появляется вкладка «Планы»: карточка на каждый представленный план, свежие сверху, с номером, итогом и временем.
- **Состав.** Полоса состава и счётчики разбивают список по итогам; чипы фильтруют его, у каждого свой счётчик.
- **Сам план.** Карточка — одна кнопка: нажмите её, и план откроется во встроенной вкладке просмотрщика. В списке план не рисуется, поэтому длинный план не нужно листать, а текст показывает тот же просмотрщик, что и у режима плана. Если просмотрщик план не принял, под карточкой появляется строка об этом — клик не молчит.
- **Страница.** Вкладка в центральной колонке рядом с Chat и Trajectory: слева фильтр и карточки, справа сводка и карточка сессии.
- **Импортированные сессии.** Планы сессий Claude Code, перенесённых в DSH, тоже читаются: там тот же инструмент называется `ExitPlanMode`.

Панель только читает журнал сессии: ничего в него не пишет и подтверждений не запрашивает.

## Установка

```sh
dsh plugin --profile <профиль> add dsh-plans
```

Из чекаута вместо имени передаётся `./dsh-plans`, а из репозитория — адрес целиком: `dsh plugin --profile <профиль> add https://github.com/Vertudo/dsh-plans`. Тот же бандл ставится со страницы плагинов: диалог добавления принимает имя пакета, адрес Git, архив или локальный путь.

Нужен DSH `>= 0.2.2 < 0.3.0` — это объявлено в `engines.dsh`, и несовместимый выпуск отклоняется при установке и при старте профиля. Обновление — удалить бандл и поставить заново: установка поверх уже установленного пакета возвращает `already-installed`. Перезапустите DSH (или перезагрузите окно), чтобы браузер подхватил клиентскую часть.

## Где появляется

Три поверхности, один компонент:

- **Встроенная правая панель DSH** — вкладка добавляется из гида: нажмите кнопку добавления и выберите «Планы».
- **dsh-better-sidebar** — в его списке вкладок «Планы» появляются сразу, настраивать ничего не нужно.
- **Центральная колонка** — вкладка «Планы» рядом с Chat и Trajectory, на всю ширину.

Строка списка — одна кнопка: клик открывает план в отдельной вкладке просмотрщика. Поэтому прочитать план можно, только когда доступна штатная правая панель; если её нет, карточка сообщает об отказе. У страницы, кроме того, есть «Открыть в панели».

## Как пользоваться

1. Откройте правую боковую панель в сессии, где работал режим плана, или выберите вкладку «Планы» в шапке.
2. В панели добавьте вкладку «Планы»: кнопка добавления открывает гид, где «Планы» — одна из плиток.
3. Нажмите строку плана — он откроется во встроенной вкладке просмотрщика. В самом списке план не раскрывается.

Список читается при открытии панели. После нового плана в той же сессии нажмите «Обновить».

## Как устроено

План — не объект сессии: это вызов `exit_plan_mode`, у которого аргумент `plan` содержит markdown, показанный пользователю. Итог — запись `tool/result` с тем же `callId`. Поэтому каждая поверхность сама сворачивает журнал сессии:

- `ctx.remote.session.events` и `ctx.remote.session.page` читают журнал страницами, включая историю глубже первой страницы;
- вызовы `exit_plan_mode` и `ExitPlanMode` становятся карточками, а их итоги — точками, подписями и полосой состава;
- план открывается адресом `dsh-resource://plan/<сессия>/<callId>`: его узнаёт встроенный тип вкладки `plan` и рисует сам, поэтому плагину не нужен ни markdown-рендер, ни собственный разбор;
- отказ просмотрщика (нет штатной панели, нет типа вкладки, план без заголовка) печатается строкой под карточкой, а не теряется молча.

Визуальный слой — один файл `src/client/panel.css` на токенах `--dsw-alias-*`. Он едет внутри клиентского бандла и вставляется одним элементом `<style>`, поэтому светлая и тёмная темы следуют за приложением без второго файла. Поверхности регистрируются в `sidebar.right.pane.tab`, `betterSidebar.registerTab` и слоте `conversation.view`.

Поэтому в плагине один клиентский модуль и пустая хостовая половина: строка в профиле оставляет бандл адресуемым, а настройки можно добавить позже, не переименовывая её.

## Ограничения

- **Только текущая сессия.** Список показывает ту сессию, в чьей панели или вкладке он открыт; обзора по всем сессиям нет.
- **Обновление вручную.** План, представленный при открытой панели, появится после «Обновить»: журнал по таймеру не опрашивается.
- **План читается только в просмотрщике.** Список показывает название, итог и время; текст плана — во встроенной вкладке. Если вкладки `plan` или штатной правой панели нет, карточка сообщает об отказе, и план не открыть.
- **Замечания ревью не показываются.** В карточке виден итог, но не текст замечаний: он остаётся в журнале сессии.
- **Импортированные сессии.** План из сессии Claude Code помечен как `Claude Code`; встроенный просмотрщик ищет его в той же истории сессии.

## Разработка

```sh
npm install
npm run build        # lib/index.js + lib/client.js
npm test             # юнит-тесты
npm run verify       # гигиена + тесты + сверка сборки
```

`lib/` коммитится: `npm run verify` падает, если закоммиченная сборка расходится с исходниками. Исходники — обычные ES-модули; клиентский бандл оборачивается для загрузчика Web в `scripts/build.mjs`, `react` и `@deepseek-ai/dsh-client-ui-primitives` приходят из таблицы модулей браузера, а стили едут через `text`-загрузчик, поэтому бандл остаётся одним JavaScript-файлом.

`design/` — согласованный макет (`mock.html`: обе поверхности, обе темы), рендерер превью (`render-preview.mjs`), который рисует собранный код настоящим stylesheet, и снимки в `design/screens/`. В пакет ничего из этого не попадает: `files` в `package.json` каталог не перечисляет.

Фикстура в `tests/fixtures/` — урезанный фрагмент настоящей сессии: четыре вызова `exit_plan_mode` из сессии репозитория backend_docs и их результаты.
