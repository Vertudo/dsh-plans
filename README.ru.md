# dsh-plans

[English](README.md) | Русский

Все планы, которые сессия DeepSeek Harness представляла на проверку, — свежие сверху, в правой боковой панели.

Режим плана и без плагина показывает план по одному: пока план ждёт решения, открывается его вкладка, а после хода в ленте остаётся карточка. Чего нет — общей истории сессии. Плагин её добавляет: одна панель, все представленные планы и итог каждого.

## Что получаете

- **Список.** В правой панели появляется вкладка «Планы»: строка на каждый представленный план, свежие сверху, с номером, итогом и временем.
- **Сам план.** Нажатие на строку открывает план во встроенной вкладке плана — том же просмотрщике, которым пользуется режим плана, с той же вёрсткой markdown и восстановлением из истории.
- **Итог.** В строке видно, утверждён план, отправлен на доработку (с замечаниями ревью) или отклонён до утверждения.
- **Импортированные сессии.** Планы сессий Claude Code, перенесённых в DSH, тоже читаются: там тот же инструмент называется `ExitPlanMode`.

Панель только читает журнал сессии: ничего в него не пишет и подтверждений не запрашивает.

## Установка

```sh
dsh plugin --profile <профиль> add ./dsh-plans
```

или добавьте бандл со страницы плагинов. Перезапустите DSH (или перезагрузите окно), чтобы браузер подхватил клиентскую часть.

## Где появляется вкладка

Встречаются две реализации боковой панели, и плагин регистрируется в обеих:

- **Встроенная правая панель DSH** — вкладка добавляется из гида: нажмите кнопку добавления и выберите «Планы».
- **dsh-better-sidebar** — в его колонке вкладка «Планы» появляется сразу, настраивать ничего не нужно.

Строка разворачивает план прямо в списке, поэтому читать можно в любой колонке. Там, где есть встроенная правая панель, у развёрнутого плана есть ещё и переход в штатный просмотрщик.

## Как пользоваться

1. Откройте правую боковую панель в сессии, где работал режим плана.
2. Добавьте вкладку «Планы»: кнопка добавления открывает гид, где «Планы» — одна из плиток.
3. Нажмите строку, чтобы прочитать план. Повторное нажатие фокусирует уже открытую вкладку, а не открывает вторую копию.

Список читается при открытии вкладки. После нового плана в той же сессии нажмите «Обновить».

## Как устроено

План — не объект сессии: это вызов `exit_plan_mode`, у которого аргумент `plan` содержит markdown, показанный пользователю. Итог — запись `tool/result` с тем же `callId`. Поэтому панель сама сворачивает журнал сессии:

- `ctx.remote.session.events` и `ctx.remote.session.page` читают журнал страницами, включая историю глубже первой страницы;
- вызовы `exit_plan_mode` и `ExitPlanMode` становятся строками списка;
- строка открывает `dsh-resource://plan/<сессия>/<callId>` — адрес, который узнаёт встроенный тип вкладки `plan` и рисует сам.

Поэтому в плагине один клиентский модуль и пустая хостовая половина: строка в профиле оставляет бандл адресуемым, а настройки можно добавить позже, не переименовывая её.

## Ограничения

- **Только текущая сессия.** Панель показывает ту сессию, в чьей боковой панели она открыта; обзора по всем сессиям нет.
- **Обновление вручную.** План, представленный при открытой вкладке, появится после «Обновить»: панель не опрашивает журнал по таймеру.
- **Рисует встроенная вкладка.** Вид плана — дело встроенного просмотрщика. Если в поставке его уберут, строки останутся, а открывать планы будет нечем.
- **Импортированные сессии.** План из сессии Claude Code помечен как `Claude Code`; встроенный просмотрщик ищет его в той же истории сессии.

## Разработка

```sh
npm install
npm run build        # lib/index.js + lib/client.js
npm test             # юнит-тесты
npm run verify       # гигиена + тесты + сверка сборки
```

`lib/` коммитится: `npm run verify` падает, если закоммиченная сборка расходится с исходниками. Исходники — обычные ES-модули; клиентский бандл оборачивается для загрузчика Web в `scripts/build.mjs`, `react` приходит из таблицы модулей браузера.

Фикстура в `tests/fixtures/` — урезанный фрагмент настоящей сессии: четыре вызова `exit_plan_mode` из сессии репозитория backend_docs и их результаты.
