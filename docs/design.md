# dsh-plans — дизайн

Статус: на согласовании. Код не пишется до утверждения.

## Задача

В сессии DSH, где работал режим плана, показать все составленные планы — свежие сверху — и дать открыть каждый. Место показа: правая боковая панель. Область: строго текущая сессия.

## Что выяснено в установленном DSH (0.2.2-rc.5)

Плана как сущности нет: план — это вызов `exit_plan_mode({ plan })`, где `plan` — markdown, начинающийся с `#`-заголовка. Событие `plan/mode { active }` отмечает только вход и выход из режима. Судьба плана видна по `tool/result` того же `callId`: `{ approved: true }`, `{ approved: false }` либо ошибка с замечаниями.

Штатный пакет `@deepseek-ai/dsh-client-ui-plan` уже умеет просмотр, и это снимает половину работы:

- тип вкладки `plan` с `id`, приоритетом `builtin` и шаблонами адресов `dsh-resource://plan/**`, `dsh-resource://plan-review/**`;
- провайдер ресурса читает историю сессии через `ctx.remote.session.events({ address: { kind: 'session', sessionId } }, signal)`, листает страницы до нужного `callId`;
- адрес плана: `dsh-resource://plan/<encodeURIComponent(sessionId)>/<encodeURIComponent(callId)>`;
- открытие: `ctx.sidebarRight.openResource(planAddress(...))` — вкладка встаёт в правую панель, переживает перезагрузку страницы, повторное открытие фокусирует существующую.

Чего нет: общей ленты планов по сессии. Штатные карточки появляются в конце **каждого хода** (`conversation.chat.turnTail`), то есть планы разбросаны по ленте диалога. Отсюда задача плагина — собрать их в один список.

Доступ к журналу на клиенте уже есть: `ctx.remote.session.events` отдаёт `{ records, hasMore, cursor }`, запись `tool/call` содержит `callId`, `name`, `arguments`.

## Решение

Плагин клиентский: строка в бандле плюс клиентский модуль. Хост-кода нет.

1. Тип вкладки `plans` (`kind: 'plans'`, `id: 'dsh-plans'`, `priority: 'extension'`, без `patterns`) — страница, открывается `ctx.sidebarRight.openTab('plans')`. Вход: плитка на странице-гиде (`guide`), плюс `openTab` из консоли браузера на время отладки.
2. Тело вкладки: читает журнал текущей сессии, отбирает `tool/call` с именами `exit_plan_mode` и `ExitPlanMode`, разбирает `arguments.plan`, берёт заголовок из первой строки `# `, статус — из соответствующего `tool/result`.
3. Список — по убыванию времени: номер, заголовок, время, статус. Клик по строке — `ctx.sidebarRight.openResource(<адрес плана>)`, дальше читает штатный просмотрщик.
4. Кнопка «Обновить» и перечитывание журнала при появлении новых записей.
5. Плагин только читает: в журнал не пишет, разрешений не требует.

## Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| Свой рендер markdown в теле вкладки | Дублирует штатный просмотрщик и расходится с ним по вёрстке; достаточно открыть адрес |
| Хост-сканирование `~/.dsh/sessions/*.jsonl.zstd` (Typert-методы) | Клиент видит ту же историю через `session.events`, включая страницы глубже первой; свой транспорт, дескрипторы и zstd не нужны |
| Страница в левом сайдбаре (как у `dsh-opencode-go`) | Пользователь просил боковую панель; правый сайдбар уже владеет просмотром плана |
| Своё событие «план добавлен» через `ctx.remote.$on` | Плагин не может публиковать свои события: `$on` работает по allowlist хоста |

## Модель записи

```ts
interface PlanEntry {
  n: number            // номер от старых к новым
  callId: string
  seq: number
  time: number
  source: 'dsh' | 'claude'
  title: string        // первый '# ' заголовок, иначе «План N»
  status: 'approved' | 'revise' | 'dismissed' | 'unknown'
}
```

`n` считается по возрастанию, отдаётся в обратном порядке — «свежий сверху» получается без пересчёта на клиенте.

## Конфиг

| Поле | По умолчанию | Смысл |
|---|---|---|
| `includeImported` | `true` | показывать планы импортированных сессий Claude (`ExitPlanMode`) |
| `refreshSeconds` | `5` | период перечитывания, пока вкладка видна; `0` — только по кнопке |
| `maxPlans` | `100` | сколько последних планов держать в списке |

## Проверки

- Юнит: `extract` на фикстурах — четыре реальные сессии из `backend_docs` («Давай подготовим през» и соседние) и одна импортированная Claude-сессия; сверка заголовка, статуса и порядка.
- Клиент: jsdom-тест регистрации типа вкладки и отрисовки списка на подставном remote.
- Живая: в сессии «Давай подготовим през» список показывает 4 плана свежим сверху, каждый открывается штатной вкладкой.
- `npm run verify` зелёный: typecheck, hygiene, тесты, сборка клиента, `check:dist`.

## Риски и как снимаем

| Риск | Что делаем |
|---|---|
| Штатный `submittedPlan()` отбирает только `exit_plan_mode`, поэтому адрес импортированного плана может не открыться | Первый опыт: открыть адрес плана из Claude-сессии. Если не открывается — строка помечается как «импортированный», текст показываем своим фолбэком во второй итерации |
| Тело вкладки может не знать `sessionId` | Проверяем на первом же запуске; если в props нет — берём из контекста таба (`useTabInfo`) или из `ctx` сессии |
| Слоты менялись между 0.2.1 и 0.2.2 | Всё пишем под 0.2.2-rc.5 (установленная версия), `dsh.client.inject` перечисляет нужные пакеты явно |
| Клиентский бандл подхватывается только перезагрузкой окна | В проверке перезагружаем окно и убеждаемся, что панель новая |

## Критерии приёмки

- Плитка «Планы» на странице-гиде открывает вкладку в правой панели.
- В «Давай подготовим през» — 4 плана, свежий сверху, с заголовком, временем и статусом.
- Клик открывает план целиком штатной вкладкой; повторный клик фокусирует ту же вкладку.
- Импортированная Claude-сессия показывает планы; если просмотр недоступен — это видно в строке, а не молчаливой ошибкой.
- Подписи меняются вместе с языком интерфейса; непереведённых ключей нет.
- Журнал сессии после работы плагина не изменился.
