# dsh-plans — дизайн

Статус: реализовано в 0.2.0. Визуальный эталон — `design/mock.html` (согласован 23.11.2026); как выглядят настоящие компоненты с настоящим `panel.css` — `design/preview-light.html` и `design/preview-dark.html`.

## Задача

Показать все планы, которые сессия представляла на проверку, и дать открыть каждый. Задача дизайна — не «сделать красиво», а вписать панель в язык интерфейса DSH: до 0.2.0 панель рисовалась inline-стилями с рамками `currentColor` и текстом плана в `<pre>`.

## Что выяснено в установленном DSH (0.2.2-rc.5)

- **Токены темы.** `--dsw-alias-*` в `dsh-client-ui-theme/src/styles/design-platform.css`: поверхности `bg-base`, `card-fill`, `card-fill-hover`; текст `label-primary|secondary|tertiary`; линии `border-l1..l4`; статусы `state-success|warn|error|idle-primary`; наведение `interactive-bg-hover`; скелетон `bg-skeleton`; радиусы `--dsw-radius-*`; моноширинный `--ds-font-family-code`. Тёмная тема — `body[data-ds-dark-theme]`, значения переопределяются сами, отдельный stylesheet не нужен.
- **Markdown.** Штатный просмотрщик плана (`dsh-client-ui-plan/src/client/PlanPreview.tsx`) рендерит план через `MarkdownText` из общего модуля `@deepseek-ai/dsh-client-ui-primitives`. Модуль базовый: dsh-context импортирует его, не объявляя в `dsh.client.inject`, а `PlanPreview` — часть поставки.
- **Страница.** Центральная колонка принимает вкладки через слот `conversation.view` (`{ id, order, locale, label }` + компонент; owner — `sessionId`). Так dsh-context добавляет Context и Fleet рядом с Chat и Trajectory.
- **better-sidebar 0.32** больше не держит свою правую колонку: вкладки плагинов он рисует в нижнем воркбенче, а правая колонка — штатная. Поэтому поверхность должна работать и в узкой панели, и в широкой.

## Визуальный язык

| Принцип | Как в коде |
|---|---|
| Карточка на спокойном фоне | `card-fill`, рамка 1px `border-l2`, радиус 10–12px |
| Подпись тише значения | подписи `label-tertiary` 11–12px, значения `label-primary`, числа `tabular-nums` |
| Статус — точка и цвет подписи | approved → `state-success-primary`, revise → `state-warn-primary`, dismissed → `state-idle-primary`, unknown → `border-l3` |
| Состав — одна полоса | сегменты 6px с радиусом 999, `role="img"` и подпись словами |
| Сворачиваемые карточки | шеврон с поворотом на `--ds-transition-duration-fast` |
| Скелетон вместо «Загрузка…» | три карточки на `bg-skeleton`, пульсация отключается при `prefers-reduced-motion` |
| Полосатый фокус | `:focus-visible` — 2px `border-selected` с отступом |
| Ни одного жёсткого цвета | все краски через `var(--dsw-alias-…)` с локальными алиасами `--plans-*` |

Типографика: заголовок панели 13px/600, страницы — 15px/600; название плана 12.8px/600, две строки с обрезкой; мета 11.2px; текст плана задаёт штатный markdown-рендер. Отступы 8/10/12/14, поля панели 12px, страницы 18×22.

## Панель

Сверху вниз: шапка (заголовок, счётчик, кнопка обновления иконкой), полоса состава с тремя счётчиками, чипы фильтра со счётчиками, список карточек. Раскрытая карточка показывает замечания ревью отдельным блоком, план рендером хоста и две кнопки: «Открыть в просмотрщике» и «Открыть страницу планов». Если рендер недоступен, карточка не раскрывается: шеврон смотрит вправо, нажатие открывает план в штатном просмотрщике, и сырой markdown не печатается.

Состояния: скелетон при первой загрузке; пустой список с подсказкой про `/plan`; ошибка с точкой `state-error-primary`, текстом и кнопкой «Повторить»; «нет планов с таким итогом» при пустом фильтре. Ширина заранее неизвестна — счётчики переносятся, фильтр переносится, отступы ужимаются на `@container (max-width: 340px)`.

## Страница

Вкладка «Планы» рядом с Chat и Trajectory. Две колонки: слева фильтр и список, справа липкая колонка с карточками «Сводка» (четыре плитки, полоса состава, пояснение) и «Сессия» (короткий id, диапазон планов, сколько импортировано, первый план, пометка «только чтение»). Самая свежая карточка раскрыта при открытии; закрытие не открывает другую.

Широкая колонка — две колонки сетки, узкая (`@container (max-width: 760px)`) — одна, карточки справа уходят под список. «Открыть в панели» на странице и «Открыть страницу планов» в панели связывают поверхности; кнопки появляются только если штатная правая панель есть.

## Тексты и время

Время строки: сегодня — `12:34`, вчера — `вчера, 12:34`, этот год — `23 ноя`, раньше — `23.11.2025`; полная метка — в `title`. Дни в карточке сессии складываются в слова «сегодня» и «вчера». Словари en/ru расширены страницей, фильтрами и подписями markdown-рендера; паритет ключей проверяется тестом.

## Архитектура

```
src/client/index.js        регистрации: тип вкладки, слот панели, вкладка better-sidebar, conversation.view
src/client/PlansPanel.js   компактная панель
src/client/PlansPage.js    страница на всю ширину
src/client/components.js   SummaryBar, KpiRow, FilterChips, PlanCard, PlanDoc, состояния, иконки
src/client/summary.js      чистые функции: счётчики, фильтры, состав, формат времени
src/client/usePlans.js     чтение журнала и фильтр как хуки
src/client/markdown.js     доступ к MarkdownText хоста; без него карточка ведёт в просмотрщик
src/client/styles.js       один <style> на документ
src/client/panel.css       весь визуал на токенах
```

## Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| Inline-стили вместо stylesheet | не выражают `:hover`, `:focus-visible`, `@container` и тёмную тему |
| Свой markdown-рендер | дублирует штатный и разойдётся с ним по вёрстке; берём `MarkdownText` хоста, а без него откатываемся на просмотрщик |
| Графики и модалка «как в dsh-context» | данных на график мало (единицы планов), модалка дублирует страницу |
| Tailwind в бандле | ради одной панели тянет компилятор и слой утилит; чище один CSS-файл на токенах |
| Эмодзи 📋 в иконке вкладки | не масштабируется и не наследует цвет; заменён SVG из `icon.svg` |

## Проверки

- `npm run verify`: гигиена, 32 теста, сверка `lib/` со сборкой.
- `tests/summary.test.mjs` — счётчики, фильтры, состав, форматы времени на фиксированном `now`.
- `tests/panel.test.mjs` — бандл рендерится мини-рендерером: скелетон → список, чтение плана на месте, переход в просмотрщик без рендера, фильтр, обе ошибки, страница с открытой свежей карточкой; отдельная проверка, что `<pre>` не появляется никогда.
- Грепом по `panel.css` не найдено жёстких цветов вне фолбэков `var(..., #…)`.
- Превью `design/preview-*.html` снято в браузере в обеих темах.

## Ограничения и что осталось за рамками

- Обновление ручное: список читается при открытии, дальше — кнопка. Живая подписка на журнал — следующая итерация.
- Только текущая сессия, обзора по всем сессиям нет.
- Если `MarkdownText` недоступен, карточка не печатает сырой markdown: нажатие открывает план в штатном просмотрщике. Текст тогда читается там, где ему и место, а не в панели.
- Состояние раскрытия не переживает перезагрузку страницы.
